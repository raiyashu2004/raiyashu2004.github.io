Indian eCourts Medallion Pipeline

An enterprise-grade lakehouse data pipeline ingesting millions of Indian judicial records with Bronze/Silver/Gold Medallion architecture, automated dbt dimensional modeling, and containerized Airflow orchestration.

GitHub Repository → Explore in Doors

How It Started & The Challenge

The Indian judiciary processes hundreds of millions of case records across thousands of District and Subordinate Courts. However, judicial open data across portals like the National Judicial Data Grid (NJDG) is heavily fragmented, inconsistent in nomenclature, and lacks structured historical tracking for case lifecycle transitions (e.g. from Filing to Hearing to Disposal).

To solve this, I designed and built an automated Medallion Data Lakehouse Pipeline. Powered by Apache Airflow, DuckDB, dbt, Great Expectations, and Metabase in a fully containerized Docker ecosystem, the pipeline ingests CNR-indexed case records, asserts strict schema validity, tracks state changes with SCD Type 2 modeling, and materializes high-velocity analytics marts.

Key Technical Innovations & Engineering Highlights

1. 3-Tier Medallion Data Engineering

The pipeline separates data ingestion into distinct evolutionary tiers: Bronze (immutable, append-only partitioned Parquet files storing raw scraped judicial payloads), Silver (cleaned, standardized tabular warehouse entities in DuckDB with court alias resolution), and Gold (aggregated dimensional star-schema data marts optimized for analytical query execution).

2. Slowly Changing Dimensions (SCD Type 2) & Data Quality Gates

Cases evolve across years. Rather than destructively overwriting status changes, the pipeline utilizes dbt snapshots implementing Slowly Changing Dimensions (SCD Type 2) with `valid_from` and `valid_to` timestamps. Before loading raw data downstream, a comprehensive Great Expectations test suite enforces non-null CNR numbers, valid case year ranges, and structural integrity.

3. Zero-Serverless High-Performance DuckDB Engine & Airflow DAGs

By leveraging DuckDB as the in-process columnar analytics engine alongside columnar Parquet storage, analytical aggregations across hundreds of thousands of judicial rows execute in sub-100ms speeds without incurring cloud warehouse overhead. The entire end-to-end lifecycle runs autonomously via scheduled Dockerized Apache Airflow DAGs feeding directly into live Metabase visualization boards.
